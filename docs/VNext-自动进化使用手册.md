2026-10-15新增明确的“进化并应用”入口，支持每天主动研究并应用通过历史检验的新规则；与原有长期自动进化分别记录证据。页面交互、数据等待与使用方法见[每日进化与页面交互](VNext-每日进化与页面交互-2026-10-15.md)。

2026-10-13。本版本已经实现后台参数研究、实时指数模拟观察、授权范围内策略晋升、回退与快捷执行确认。你新增的工作日共享拉取、巡检更新数据及Loading、证据/AI解读展示和中文选项保留。

2.1新增自动历史修复、基础及专业因子组合研究、默认空仓和Linux Compose文件。详细机制与云端操作见[云端自动维护与因子进化](VNext-云端自动维护与因子进化-2026-10-13.md)。

## 本地使用

1. 关闭旧启动窗口，重新双击`一键启动新版.bat`。当前工作区的`quant_system_next.db`已备份升级到schema 2，继续输入原账号名。
2. 未登记默认空仓；真实持有时在“持仓与预算”改为持有。状态保持到你修改，金额可留空；金额建议还需要基金映射、资金和预算。
3. 到“策略与研究”，选择指数，在“自动进化 · 回撤优先”保存一次配置。默认自动研究及个人巡检开启；自动晋升默认关闭，需要你明确勾选并确认授权范围。
4. 需要策略自动生效时，勾选“允许通过检验后自动更新规则并启用该指数提醒”；2.1还可授权四类固定入场因子组合，保持连续确认和均线退出规则。旧配置不自动扩权，需勾选因子研究后保存。飞书渠道仍在“通知与运行”单独开启。
5. 日常看“今日操作”。下单但未成交选“已下单，等待成交确认”；真实成交后选“已执行/部分执行”，可同时明确确认成交后的持仓；未执行选“暂缓”并说明原因。

无需每天点击研究、同步或分析。关闭网页不会取消任务；本地启动窗口与后台需保持运行，云端由Compose持续运行。Linux镜像及服务器实测仍待CI确认，GitHub远程发布自动化尚未实施。

若原启动窗口已消失但8502仍占用，一键启动会核对页面路径、后台数据库、共同启动关系和进程创建时间，自动清理已确认的本项目遗留服务后启动。其他程序、其他数据库或仍有启动器管理的服务不会被自动停止；可打开已有页面，或用`--port`指定其他端口。新环境需安装更新后的依赖文件，其中包含psutil。

## 自动研究如何运行

- 默认每30个自然日检查研究周期。均线单独研究通常12情景；2.1授权四类因子组合且数据完整时最多60情景，仍受年度试验预算限制。
- 后台每轮只计算一个历史情景，用户任务和通知优先；重启后从已完成情景继续，失败最多3次。
- 历史需完整预热及至少504个共同评估交易时段，约两年的交易日，另加均线预热。后台分批补充，不需要用户手动补历史；接口尚未提供时保留缺口并重试。
- 先在开发区间选一个候选，再检查验证/测试区间与成本/延迟情景。测试失败不改选第二名；邻近参数稳定性不足也不晋升。
- 同时比较现行策略、持续持有、按模拟持有时间比例分配的固定敞口加现金。最后一种只是相似敞口对照，不代表完全相同的风险。
- 检查回撤改善、最大观察回撤、收益损失、持有时间和交易次数。永远空仓不会因为回撤为零就获胜。
- 全部尝试保留记录；年度预算跨配置版本累计。默认180个预留情景，取消/失败也不会清空预算；研究周期内不反复重筛。

当前采用有限候选、时间顺序开发/验证/测试和未来行情观察，没有实现完整嵌套滚动选策回测或统计收益保证。旧测试区间会被消费，后续重复研究不能称为全新样本外证据。

## 实时模拟与自动更新

历史合格后在当时最新可用交易日冻结参数，默认收集**63个之后实际观察的交易日**，且至少完成2次模拟买卖。采用指数开盘点位、设定成本及成交延迟；现金收益按零，不等于场外基金成交或真实账户。

观察结束只检查一次固定期限，未通过则淘汰，不延长到碰巧通过为止。观察前历史被修订、后台漏跑交易日、规则/授权变化或数据异常时，隔离候选，不能用事后数据伪造实时观察。

晋升还需当前数据新鲜、观察证据完整、授权有效、范围符合、更新冷却期满足，且旧提醒没有正在投递。默认两次更新至少间隔90个自然日。生产参数更新有版本和证据；旧待发提醒失效，持仓与资金保持不变，后台重新计算个人判断。没有合格候选就保留当前策略。

“回退上次策略更新并暂停自动晋升”会新建旧规则的当前版本、保留审计和持仓，停用该指数自动进化配置。回退不能保证改善未来收益；重新开启需再次保存范围。

## 快捷反馈与持仓

- 单独保存处理结果不会更改持仓。
- 只有你明确勾选成交后持仓确认，才追加持仓报告；不从指数价格推算真实份额。
- 未提供的原市值和份额不沿用，变为未知。交易后的旧现金与投入本金也变为待确认，避免用旧现金生成新的金额建议。
- 部分执行仍保持持有；全部卖出确认空仓。重复点击同一确认不会重复追加报告。
- 规则/持仓已经变化时，旧反馈可以单独记录，但不允许覆盖新持仓。
- “期间未交易”只刷新状态与未变化的份额，旧市值不会被当作新估值。现金变化仍需到预算更新。

## 云端或其他数据库升级

先停止页面与后台，执行一次：

```bash
python -m clawindex_next --db /绝对路径/quant_system_next.db upgrade --backup /备份目录/before-evolution.db
```

备份路径必须是新文件。程序使用SQLite一致性备份和完整性/FK检查，再在事务内新增进化表，不改旧业务表；已有活跃后台/任务租约时拒绝升级。正常停止会清理心跳，强杀后需等租约过期。应用不会在启动时隐式升级。

当前工作区备份为`quant_system_next.before-evolution-20261013.db`。回滚整个应用/数据库与回退一个策略是不同操作：恢复数据库备份会丢失备份之后的记录，先导出新增持仓与反馈。

Linux上线仍需使用包含WAL-reset修复的Python实际链接SQLite版本，详见Linux设计。当前Windows测试不构成Linux生产验收。
