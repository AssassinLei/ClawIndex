# Gen2 系统复核与策略体检

本次升级围绕一个问题：怎样让用户花更少时间，同时清楚知道该做什么、依据是什么、实际是否成交。保留明确的买卖提示，AI继续负责解释，程序规则决定操作。

## 今日操作

- 暂缓显示“已暂缓，尚未成交”，仍计入待决定；尚未执行的退出优先展示。
- 已提交和部分成交显示待跟进，先核对实际订单，避免重复下单，不自动认定已经成交。
- 处理结果需要主动选择，取消默认“已提交”。只有已成交或部分成交时，才允许同步确认真实持仓；改成暂缓时清除旧勾选。
- 展示最近规则触发日期、持续成立的条件与判断有效期。当前入场条件仍成立，并不意味着今天又出现了新信号。
- 后台更新判断后，已展开的数据、解读或曲线继续显示，使用新判断自己的证据；历史记录保留原版本。

系统不能替用户下单，也不能自动获知实际成交。未登记持仓仍默认空仓；实际持有时请更新持仓状态，否则系统继续按空仓判断。

## 策略体检

进入“策略与进化”，展开“策略体检：现行规则的证据与代价”。只读取本账号已保存的证据，不启动巡检、研究、数据接口或AI请求。

检查对象是当前正在使用的规则。研究中的候选另行展示，不把候选观察进度算成现行规则的验证结果。

| 展示内容 | 含义 |
| --- | --- |
| 暂无可用检验证据 | 当前尚无匹配的历史报告 |
| 已有历史模拟 | 有相同规则、成本与延迟的试验；仍需新行情验证 |
| 依据历史检验更新 | 每日进化实际改过参数，尚未通过固定前向观察 |
| 前向证据待核实 | 保留更新记录，但冻结时间、固定观察期或逐日证据不完整 |
| 通过固定前向观察门槛 | 逐日模拟证据完整，重算后仍通过当时的研究条件 |

有匹配报告时，展示历史最大收盘回撤、相对持续持有少赚多少、模拟持有时间及交易次数，并列出不同成本和延迟的压力情景。“少赚”为负表示这段历史多赚，并非未来预期收益。

标明试验区间、生成时间及是否与当前巡检使用相同数据版本。超过用户设置的回撤、机会成本或交易频率门槛时明确提示。旧试验不能称为最新效果；零成本或其他参数的结果不会替代当前假设。

后台历史试验必须完成所有预定情景，每项规则、成本、延迟须对应。旧记录只有“启用”状态不足以证明前向通过。查询先选择匹配的来源，再加载对应规则的情景，避免一次载入多轮完整曲线。

这些是指数价格模拟，不能代替实际基金净值、申赎、分红、汇率或账户收益。研究回撤门槛不能保证未来亏损上限；缺少持仓权重和账户现金时，系统不能证明整个账户的组合风险受控。

## 策略进化

- 自动研究间隔按账号和指数计算，重新保存设置不能绕过研究周期。
- 邻近参数也必须满足回撤、收益代价、最低持有时间和交易频率条件，避免把几乎一直空仓的参数当成稳定性证据。
- 转入新行情观察前重新核对历史数据。研究期间发生修订时，本轮不用于冻结候选，保留现行规则与审计记录。
- 每日仍可点击“进化并应用”。行情、规则、设置和算法未变化，且此前已完整研究并否决时，复用结果并显示原研究时间，不再搜索相同参数。
- 输入变化、失败或不完整的研究，不作为成功复用依据。仅依据历史应用规则仍与长期自动进化的固定前向观察区分。

频繁依据相近历史改参数不构成新验证。用户可以主动进化，但反复使用同一段历史不算新增收益证据。

## 机会通知

保留“只发送目前存在的机会”：投递前重新检查当前机会、个人偏好和渠道设置，不发送撤销通知。

尚未实际送达、下一次扫描仍有效的机会，可接续到最新行情版本，避免因等待周二/周四等Cron窗口而永久漏发。已经送达且阶段未变化的机会不因此每天重发。接续保留真实发送次数和失败后的重试间隔，旧重复记录不能绕过三次尝试上限。

后台在任务批次前、任务之间及指数同步之间检查通知，减少长批次占用发送窗口。单次外部请求仍可能阻塞到超时；Cron是允许发送的窗口，不承诺精确到秒送达。
