# Gen2 稳定版本全面验收

本次按数据与判断、研究证据、长期后台、通知、用户操作、部署和恢复逐项复核。优先修复会造成错误判断、反复忙、重复通知、失败后无法恢复的真实问题，不扩大策略搜索范围或增加新的交易条件。

## AI额度不足时怎么使用

数据同步、程序规则、策略研究、机会扫描和按已启用规则产生的Webhook提醒均不依赖AI生成解读。AI失败不会改变已有买卖判断，也不会让已完成巡检整项重试。

明确余额不足、认证或权限错误后，自动AI请求暂停六小时；限流暂停一分钟，模型/参数/配置错误暂停半小时。期限后允许后台下一次请求再检查。修改密钥、接口、模型或请求配置会使用新的暂停范围。UI标明原因与恢复时间；在指数的解读区域单独点击生成/重试，可立即尝试，不必重复巡检或补数据。若服务仍不可用，继续展示明确标记的程序解读。

暂停状态保存在现有数据库设置中，网页或后台重启后仍有效。只记录固定诊断与时间，不保存服务商原始错误、密钥或提示词。单个超时不会长期阻止其他指数调用。并发请求在第一个错误返回前可能已经在途，暂停不能撤回已经发出的请求。

## 升级后的注意事项

- 停止监控的L1、L2指数同时进入机会雷达的“暂不关注”。需要重新展示时，在“发现机会”恢复关注；此前的历史仍可查看。
- 旧前向观察缺少新版证据校验标记时，保留现行规则和历史记录，后续按设置重新研究。不会把升级前无法核实的观察直接当作已通过。
- 测试覆盖当前规则触发、持仓与反馈、数据范围与缺口、图表、账号隔离、AI失败、研究与进化、Cron、投递、启动和部署。功能与历史模拟的正确性不等于未来盈利证明。
- 账号名用于朋友之间分开保存资料，不验证真实身份；云端入口应按既定的私用范围开放。没有重新引入密码。

## 验证方法与边界

本地验收结果：完整回归 **657项通过（491.37秒）**；随后追加的规则编辑配置保护回归 **1项通过（4.34秒）**，共658项。`compileall`、差异检查、部署脚本与运维文档Bash代码块的语法检查通过。完整回归与追加回归分别保存在本地忽略目录 `reports/2026-10-29-stability-release-tests.xml`、`reports/2026-10-29-rule-edit-preservation-tests.xml`。

所有测试使用隔离数据库和模拟服务，没有修改生产库，也没有调用真实Tushare、AI或Webhook。包含真实SQLite WAL在线备份：保持旧读事务时写入新持仓，导出一致性备份，再仅凭导出主库在独立目录恢复，核对新持仓完整保留，并确认拒绝覆盖已有数据库。

本机为Windows，没有Docker可执行环境。Linux构建、服务器网络、磁盘余量和开机恢复不以本地测试冒充实测。GitHub公开CI接口本次返回匿名请求限流，不能据此确认Linux CI结果。服务器更新后以两个服务的健康状态、数据库状态和运行日志验收。

Webhook发送前仍会核对当前机会、用户偏好、渠道和判断有效性。已经进入HTTP传输的消息无法撤回；网络超时时无法绝对判断对方是否已经收到，因此重试不构成端到端恰好一次投递保证。

## 更新与维护

本次无需新增环境变量、依赖或数据库表，现有数据和配置继续使用。

```bash
cd ~/ClawIndex-Gen2 &&
sudo bash deploy.sh update &&
sudo bash deploy.sh status
```

更新脚本先备份，再拉取Gen2、构建并重启网页和后台。日常查看“今日操作”；实际成交或持仓变化时记录，不需要每天手动补数据或点击进化。

运行正常后，建议执行一次导出并下载到本地留存：

```bash
sudo bash deploy.sh export-db
```

日志、停启、开机恢复以及不接触生产卷的恢复演练，见[稳定版本运维简表](Gen2-稳定版本运维简表.md)。
