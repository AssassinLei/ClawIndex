# Webhook自定义发送时间

在“通知与运行”中，找到对应的Webhook，展开“自定义发送时间（Cron）”，勾选“按Cron定时发送”，填写表达式，点击“保存发送时间”。页面会校验并显示接下来三次计划时间。新建Webhook也可以同时保存时间配置。

每个账号、每个Webhook独立配置。时区固定为北京时间（Asia/Shanghai，UTC+8），不跟随Linux服务器的时区。保存立即作用于后续发送检查，无需重启或重新巡检。

## 常见表达式

Cron是标准五字段：`分 时 日 月 周`，支持列表、范围、步长、英文月份与星期。

| 表达式 | 含义（北京时间） |
| --- | --- |
| `30 19 * * mon-fri` | 周一至周五19:30 |
| `0 9,15 * * mon,wed,fri` | 周一、周三、周五09:00和15:00 |
| `*/30 9-15 * * mon-fri` | 周一至周五09:00到15:30，每半小时 |
| `0 10 * * sun` | 每周日10:00 |
| `0 9 1 * *` | 每月1日09:00 |

星期数字使用标准Cron约定：0或7为周日、1为周一、6为周六。推荐用`mon-fri`、`mon,wed,fri`等名称，避免数字歧义。旧版采用APScheduler，数字星期从0=周一开始；因此不把旧版全局配置自动复制到新版渠道。月份日期与星期都受限制时，遵循标准Cron的“或”语义，例如`0 9 1 * mon`是每月1日或每周一09:00。解析基于[croniter维护文档](https://github.com/pallets-eco/croniter)。不支持秒、年份或随机调度。

## 实际发送规则

- 默认即时发送，升级不会改变已有Webhook的发送时段。
- Cron只约束这个Webhook的正式操作通知与机会通知，不延迟行情同步、巡检或AI分析。
- 每次计划时间开始后，有5分钟发送窗口。例如19:30允许在19:30:00到19:34:59发送。后台每轮会优先检查一小批操作通知，再处理耗时的数据/AI任务；依然是尽力调度，不保证精确到秒。
- 后台离线或繁忙超过窗口时，不在窗口外补发，继续等下一个允许时段。容错不跨自然日，例如周日23:59的计划不能在周一00:00补发。
- 没到时间时，提醒留在队列，不计发送尝试。一个地址等待Cron不会挡住其他可以发送的地址；失败重试也必须同时满足重试间隔和发送窗口。
- 发送前仍检查渠道开关、筛选范围、机会条件、证据、个人上下文和过期时间。到点不代表旧提醒一定发送；过期、已处理或失效的提醒不能因为Cron而复活。
- Cron不自动排除法定节假日。行情和判断仍按照各自市场交易日历检查。
- 不是定时重复广播：没有新的有效提醒就不发送，原有去重继续生效。
- “发送测试消息”和未保存地址的“你好，世界”测试始终立即发送。保存、校验和预览本身不发送消息。
- 取消“按Cron定时发送”并保存，会恢复即时发送。若想完全停止推送，应关闭Webhook总开关；机会提醒也可单独关闭。

配置保存在现有settings表中，不需要重建数据库。非法输入不会覆盖原配置；已保存配置损坏时暂停该渠道正式发送并提示修复，不自动降级成即时发送。

## 服务器更新

```bash
cd ~/ClawIndex-Gen2
sudo bash deploy.sh update
sudo bash deploy.sh status
```

更新会安装锁定的Cron解析依赖，并重启web和worker。不要再次执行`install --empty`。
