# 行情缺口和重复分析

## 如何理解“有今天点位，但历史不足”

默认规则需要120日均线及其5日变化，因此需要最近125个连续有效交易日。总记录很多、最新一条有收盘点位，都不能证明这125天没有断档。不能把缺失日期简单删除再计算均线，也不能拿昨天的价格填补。

2026-10-16提供的云端一致性备份中，恒生科技有1977个不同日期，但2026年第三季度的65个港股交易日整段缺失。最新收盘4108.24存在，120日均线仍无法计算。纳斯达克近期数据完整，同样的规则可以正常计算。

这里指云端新版库`observations`表中缺记录，不表示旧版或Tushare没有数据。逐日对照得到：

| 数据库 | 恒生科技2026年第三季度 |
| --- | --- |
| 旧版`quant_system20261012.db` | 64天，7月2日至9月29日；开、高、低、收全部完整有效，这份快照截至9月29日 |
| 本地新版`quant_system_next.db` | 65天，7月2日至9月30日 |
| 提供的云端新版备份 | 0天，整段日线未写入，包含均线所需的收盘价 |

海外专业因子不适用，不是本次无法计算均线的原因。云端从空库启动会独立拉取，不自动读取另一台机器的旧库。旧备份没有保留每次接口返回条数，因此不能仅凭它断言首次缺失请求是接口空返回还是暂时失败；新的补齐明细会记录日期范围、返回条数、更新条数及空返回/请求失败状态。

旧维护逻辑在首次请求某季度未获得数据后，统一等6小时才重试；其间继续补更早的年份，每批又重复查询近期价格并改变全库证据版本，导致巡检和AI反复生成相同内容。最近8次恒生科技分析的当前特征和规则判断一致，说明用户看到的重复有实际依据。

## 修复后的行为

- 优先补齐当前规则需要的近期窗口。关键季度缺口不再受旧版6小时重试记录阻挡；整季度未取得数据时，每批最多额外尝试一次更短区间。有进展时约2分钟后继续，无进展时约30分钟后再试。
- 旧历史分批补充，不再每批重拉已经检查过的最新行情。补不回的旧区间逐步延长重试间隔，最高24小时；不是永久跳过缺口。
- 恒生科技用于完整开高低收的规则和交易回测，从2020-07-27起处理。以前保存的回溯收盘价保留，但不再把缺失的开高低无限重试，也不伪造可成交行情。[恒生指数公司资料](https://www.hsi.com.hk/static/uploads/contents/en/dl_centre/factsheets/hsteche.pdf)列明该指数发布于2020-07-27，基日为2014-12-31；本次备份及本地接口历史记录显示早期仅有收盘价。
- 价格接口不提供的估值字段，不再覆盖其他接口已经补齐的估值。估值接口自身明确返回空值仍会记录，真实价格修订仍会保存。
- 自动巡检与页面统一采用北京时间。自动任务复用当天当前的手动巡检；只缺AI时仅补解读。
- 真正的数据修订仍重新计算程序信号并保存证据。当前特征、规则状态、操作判断、数据日期、模型等解释依据相同时，同一账号同一指数复用已成功的AI解读，页面明确显示复用及原生成时间。不同账号不共用，依据改变或模型改变时重新生成。
- 数据证据页显示规则需要多少天、当前连续有效多少天，以及具体缺失或异常日期。同步记录区分“最新行情已到达”和“历史仍待补齐”。

首次更新会因特征版本变化重新巡检一次。之后有新行情、真实证据修订、用户持仓/资金变化、新规则或跨本地日期时，仍可能正常更新；后台心跳和定期检查不等于重新拉行情或调用AI。

## 立即重试缺口

在“我的指数”选择指数，点击“立即补齐缺口”；也可以在“今日操作 → 查看数据”中点击同名按钮。

- 请求保存在后台任务中，不受“今日已分析”及已保存成功行情缓存的限制。已有缺口的等待时间会重置，保留每批请求数及接口限速，未完成部分由后台继续。
- 相同待执行请求合并。当前普通巡检已开始时，会追加一个补齐任务，不把“强制重试”错误地并入已经结束同步步骤的任务。
- 保留正确行情、原始修订、历史判断、反馈和策略记录。补齐后重新计算程序判断，AI按用户开关处理，相同解释依据可复用。
- 页面显示总缺口、当前规则关键窗口缺口、上次更新条数，以及最近请求范围和接口返回结果。接口持续不提供时保留缺口，不用填充数据伪造成功。

## 更新后一直显示“等待更新”的兼容修复

恒生科技的旧快照包含正式发布前仅有收盘价的记录，这些记录可能是最后插入的，修订ID更大。缩小分析范围后，如果仍将范围内结果和全库最大ID比较，新结果会被误判为过期，甚至被挡在当前结果指针之外。

有效期校验、自动巡检去重、手动巡检缓存和结果替换已统一使用相同数据范围。新旧快照先按同一范围比较，再检查真实修订及日期，仍阻止旧数据或旧日期覆盖新结果。用云端备份隔离重放确认：不删除、不补写任何行情，也可以正确替换旧快照；此时状态应是“暂不能判断（历史不足）”，而不是永久“等待更新”。补回实际缺口后才继续给有效判断。

## 更新与导出

```bash
cd ~/ClawIndex-Gen2 &&
sudo bash deploy.sh update &&
sudo bash deploy.sh status
```

无需删除或重新导入数据库；后台会根据现有记录自动补齐。接口持续不可达或未提供对应区间时，会保留“暂不能判断”，不会承诺一定在固定时长恢复。

下载数据库可执行`sudo bash deploy.sh export-db`，然后用SFTP下载项目目录里新生成的`clawindex-export-*.db`，无需进入Docker内部目录。详情见[Linux部署说明](Gen2-Linux部署.md#7-备份与恢复)。
