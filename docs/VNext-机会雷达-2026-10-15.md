# 发现机会：机会雷达首版

系统原来回答“你关注的指数，今天怎么办”。这个入口新增一个问题：“还有哪些没关注的行业，出现了值得进一步跟踪的条件？”

它提供少量研究候选。首版规则固定，尚未证明有持续赚钱能力，不自动替用户买卖，也不把排名转换成赚钱概率。

## 日常怎么用

1. 更新后同时启动页面和后台 worker，进入左侧 **发现机会**。
2. 第一次由后台建立目录、分批补齐历史。可以关掉网页，服务器会继续运行；不需要用户手动同步。
3. 有候选时，先看“继续观察 / 研究入场条件满足”、入选理由，以及“风险与失效条件”。
4. 感兴趣就点 **加入我的指数**。后台接续现有行情维护和个人判断；以后在 **今日操作** 查看。新监控从研究阶段开始，不自动开启正式交易通知，已有监控不会重置策略。
5. 不感兴趣点 **暂不关注**，以后可从“我的隐藏列表”恢复。这只影响本人的展示与机会提醒。

“刷新机会”提交共享后台任务，不在页面里等待接口；同一交易日已有当前规则的完整扫描时直接提示复用。行情或规则变化后，后台重新检查。默认隐藏已关注指数，可取消勾选。

没有候选是正常结果。页面不会为了显示三条而从下跌行业中硬挑“最不差”的行业。

## 只分析 L1、L2

扫描池来自 Tushare 的申万 SW2021 分类：**L1 一级行业 + L2 二级行业**，排除 L3。沪深300仅用作共同比较基准，不进入候选排名。既有“我的指数”仍可维护其他类别，搜索目录仍可包含 L3。

行情使用同一已发布交易日。申万日线的接口字段、全市场按日提取方式和18:30更新时间，依据 [Tushare 申万日线文档](https://tushare.pro/document/2?doc_id=327)；分类依据 [申万行业分类](https://tushare.pro/document/2?doc_id=181)。接口实际权限与云服务器网络仍取决于账户和运行环境。

## 筛选的意思

先验证数据和风险，再排序，最后减少重复行业暴露。

| 检查 | 首版规则及含义 |
|---|---|
| 共同历史 | 最近260个交易日价格有效；缺失不前向填充。覆盖达到80%且基准就绪后才展示候选，未就绪指数不能入选 |
| 波动与回撤 | 20日年化波动不高于45%；当前距120日收盘高点回撤不超过20% |
| 追涨 | 高于20日均线超过10%时暂不列为候选 |
| 估值 | PE/PB各有至少252个有效样本及20种有效取值时，才使用自身历史分位；任一高于90%暂不新增候选 |
| 趋势改善型 | 60日自身上涨、相对沪深300改善，且点位和60日均线方向改善，先进入观察 |
| 研究入场条件满足 | 还须120日绝对及相对表现改善，连续3日站上120日均线、均线向上，同时基准趋势向上且已覆盖行业的上涨广度达到40% |
| 低估修复观察 | PE和PB自身分位均不高于30%，且20日价格企稳；只列观察，不因便宜就升级入场 |
| 排序与去重 | 先看确认状态、趋势类型和60日相对表现，再比较波动；父子行业及120日收益相关性达到0.85的方向不重复展示，相关性无法可靠计算时保守去重；最多3个 |

这些数值是公开留证的首版研究假设，并非已优化的最佳参数。低估值可能来自盈利恶化；目前没有成分股盈利质量验证。价格和估值证据不能直接证明行业基本面反转。

该页标注 **来源：程序筛选**，不是AI生成。加入监控后，可在已有流程里查看单独标注的AI解释。专业因子继续用于原有策略研究，首版雷达没有为了指标多而把全部指标混成一个不透明分数。

没有实际账户、基金映射和完整持仓权重时，雷达不声称评估了整个组合风险，也不给出买入金额。

## 提醒怎么开启

在 **通知与设置** 的每个已有Webhook下，单独设置“机会雷达提醒”：

- 关闭机会提醒（默认）；
- 新增机会、条件满足及撤销；
- 仅条件满足及后续撤销。

这是每用户、每地址独立的设置，与原来的“只买入 / 买入与卖出”等正式操作过滤分开。还需保持该渠道总开关开启。机会卡片明确写明研究观察及状态，不冒充个人买入指令。

状态持续不变时不天天重发。发送前重新核对行情日期、规则版本、当前条件、本人偏好及渠道；失败最多尝试3次；关闭、删除渠道或过期的排队提醒不再发送。暂时缺行情不会被误报成投资条件失效。曾经已通知的候选即使先滑出排名，条件后来失效仍会撤销提醒。

## 记录和验证

“完整筛选与撤销记录”保存未入选原因、数据未就绪情况、范围变化和每次证据版本，可下载本次共享证据，不包含私人持仓或Webhook。

“机会后来怎样”对共享排名首次出现的每个候选阶段留证，包括失败、下跌与被撤销的情况。观察20、60个交易日，从**实际展示时间之后的下一次可用开盘**起算，同期比较沪深300，模拟双边各10基点成本。中间缺价格时等待补齐，不悄悄跳过。

这是指数价格观察，不是真实基金成交、完整投资组合回测或胜率。样本可能重叠，当前分类和历史回溯也可能带来偏差。首版验证的是功能与边界行为；尚未完成真实全市场历史择时优势验证，也没有足够的长期前向样本。后续应依据这些记录评估收益代价与回撤，而不是看几个成功案例就自动扩大风险。

## Linux常驻运行与升级

- 复用现有Compose的 web 和 worker，共享SQLite卷；关闭浏览器不停止后台。
- 数据全局共享，一次拉取全体L1/L2截面供所有用户使用，不按用户倍增请求。
- 初次优先补最近260个交易日，然后继续较长历史；每轮最多6个日期并限制批次时间，沿用全局接口限速、失败冷却和进程租约，先处理已有监控任务。
- 缓存、收据、不可变扫描和通知队列保存在现有 `settings` 的 `radar:` 命名空间中；**不需要修改数据库表结构**，进程重启后可接续。
- 首次目录或历史准备耗时取决于接口、限速和已有数据。无权限时后台记录中文原因并冷却重试；不会用虚构数据继续推荐。
- 自动扫描默认跟随既有每日更新总开关；管理员可在“通知与设置”独立调整“自动扫描L1、L2指数发现机会”。

按原有发布方式更新代码或镜像，重启 **web 和 worker** 即可启用。数据库卷继续保留；不要使用删除卷的重建命令。具体一键更新方式沿用既有部署文档。

本次开发测试使用隔离数据库及合成行情，没有启动生产worker、修改生产持仓或向真实Webhook发消息。本地没有Docker环境，真实Tushare联网、镜像构建及Linux云端持续运行仍需部署后验收。
