# Webhook推送配置

在 **通知与运行 → 我的 Webhook** 中配置。每个账号只看到并管理自己的地址，同一个地址被不同账号使用时也按各自配置处理。

## 添加与测试

1. 展开“添加飞书 Webhook”，输入飞书机器人通知地址和渠道名称。
2. 点击 **测试：发送你好，世界**，立即向输入地址发送文本“你好，世界”。测试不要求先保存，不依赖后台任务，不会自动开启正式推送。
3. 选择推送方式，点击 **保存Webhook**。每个地址独立配置，新地址默认关闭。

已保存的地址也有 **发送测试消息** 按钮，即使正式推送关闭也可以测试。测试只发送问候语，不发送账户或投资数据。

## 查看与删除已有地址

每条Webhook旁有 **查看地址** 按钮，点击后显示完整地址并支持复制；点击 **隐藏地址** 收起。默认不展示地址，也不会将地址放入普通列表或导出记录。

点击 **删除 → 确认删除** 后，该地址从配置列表移除，保存的地址被清除，待发送及重试任务被取消；已经完成的投递记录保留。删除仅影响当前账号，即使其他账号使用相同地址也不受影响。已经开始的网络请求可能完成，实际尝试结果仍保留在历史中。

## 四种推送方式

| 方式 | 推送内容 |
| --- | --- |
| 关闭 | 不发送正式通知 |
| 开启（全部操作） | 买入、卖出、继续持有、空仓等待 |
| 只推送买入 | 仅买入 |
| 只推送买入、卖出 | 买入和卖出 |

筛选依据是系统**针对该账号的操作判断**，不依赖AI解读是否生成成功。更改选择后立即保存，发送前会重新核对筛选条件。

正式推送仍要求规则已启用提醒、操作判断有效且行情和持仓等输入未过期。研究观察阶段不会因为开启Webhook而自动变成正式规则。

## 卡片样式

卡片只展示两项，例如：

> 电池
>
> 操作：买入

不附加金额、持仓、原因或AI内容。买卖通知保留原有触发周期去重；持有、等待在同一行情交易日内去重。

目前使用飞书自定义机器人，支持标准 `https://open.feishu.cn/open-apis/bot/v2/hook/...` 地址。消息卡片和文本格式依据 [飞书自定义机器人文档](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot)。

## 测试失败怎么办

页面会显示具体原因和可取得的错误码，**健康**中的通知记录也会保存安全的错误说明；后台正式投递使用相同的诊断。不会记录完整地址、机器人密钥或接口原始报错。

| 提示 | 处理方法 |
| --- | --- |
| 19024：关键词校验未通过 | 到飞书群的机器人设置中，在允许的自定义关键词中分别添加 **你好，世界** 和 **操作**。前者匹配测试消息，后者匹配所有正式卡片。只让测试消息匹配关键词，还不能保证正式卡片通过校验。 |
| 19022：IP校验未通过 | 将实际运行系统的服务器出口IP加入机器人允许的IP；本地电脑与Linux云服务器可能使用不同出口。 |
| 19021：签名校验未通过 | 检查机器人签名设置与服务器时间。当前系统尚不支持配置机器人签名密钥；需要签名校验的机器人暂不能直接使用。 |
| 19001：地址或凭据无效 | 从机器人设置中重新复制当前Webhook地址。 |
| HTTP错误、超时、连接或证书失败 | 检查系统所在服务器的网络、DNS、代理与证书，按页面提示排查。 |

HTTP 200仅代表请求到达接口。飞书还会返回业务错误码，只有业务成功才会显示“已发送”。错误码定义参见 [飞书官方机器人示例](https://open.feishu.cn/community/articles/7298688341381546012)。

## 更新兼容性

无需数据库迁移。每个地址的筛选设置保存在已有settings表中，并关联用户和渠道；已有地址继续保持原来的开关状态，原先开启的地址按买入、卖出筛选。不会因更新而自动扩大发送范围。

更新代码后重启页面和后台服务。已经排队的通知也会在发送前按最新筛选检查，并转换为上述简洁卡片。
