# 电池AI解读失败：排查与修复

## 已核实的情况

本地生产库中的电池指数 `801737.SI` 存在AI解读失败记录，最近一条失败时间为2026年10月14日22:03（香港时间），所用模型为 `deepseek-v4-flash`。原程序把接口异常和内容校验异常合并成一条笼统日志，没有保存异常类别，因此无法从旧记录追溯那一次的确切错误。

只读检查数据库后，使用**合成样本**检查当前模型接口，未向外部重放真实投资记录：

| 请求配置 | 实测结果 |
| --- | --- |
| 原配置：20秒超时，未指定思考模式 | 约22.05秒后报 APITimeoutError |
| 对照：60秒超时，关闭思考，限制回答长度 | 约2.01秒返回，JSON与内容校验通过 |
| 最终修复代码的独立诊断脚本 | 约3.66秒返回 MODEL_OK |

这证明原配置存在可复现的超时问题，不表示历史上的每一次失败都是超时，也不保证后续请求不会遇到服务限流或网络问题。

另有一个可在本地确定复现的校验缺陷：原代码按子串拦截“保证收益”，连“不保证收益”“不能保证收益”等正常风险说明也会被拦截。原记录没有保存AI原文，因此不能认定电池那次必然触发了此误判。

## 修复内容

- 简短解读默认60秒超时、1800输出token；DeepSeek官方接口默认显式关闭思考模式。其他兼容接口不接收DeepSeek专用参数。
- 提示词补充JSON示例、要求引用实际提供的特征键，并保持简短。仍严格校验字段、引用与交易指令。
- 允许明确否定收益保证的常见风险说明；独立的收益保证、交易指令以及双重否定不会因此放行。
- 记录具体失败类别，例如超时、无法连接、密钥错误、余额不足、限流、参数拒绝、空回答、截断、JSON错误、未知指标引用或违规内容。
- 页面显示中文原因；诊断详情包含错误类别、处理阶段与耗时。健康日志关联对应用户与判断，未保存原始接口错误、密钥或模型原文。
- 失败后可以重试，并替换失败的程序回退记录；成功缓存与并发生成保护保留。解释版本已更新，防止继续混用旧提示词的结果。

相关接口行为参考 [DeepSeek 思考模式说明](https://api-docs.deepseek.com/guides/thinking_mode/) 和 [JSON输出说明](https://api-docs.deepseek.com/guides/json_mode/)。

## 怎么使用

重启新版页面和后台服务，进入电池卡片的“查看解读”，点击“生成AI解读”。内容开头会标明“AI生成的解读”或“程序生成的解读”；AI未成功时，展示的备用内容也会明确标为程序生成。旧失败记录不会自动改成成功；重试后会得到新结果或明确失败原因。不需要重新巡检或修改持仓。

新参数均有默认值，现有环境文件可以不修改。可选配置：

```dotenv
VNEXT_LLM_TIMEOUT_SECONDS=60
VNEXT_LLM_MAX_TOKENS=1800
VNEXT_LLM_THINKING=disabled
```

超时允许5—60秒，输出长度允许512—4096 token。上述配置会在发起请求前验证。

本地使用不含账户数据的诊断命令：

```sh
python scripts/check_next_ai.py
```

云端在更新镜像后可运行：

```sh
docker compose exec web python scripts/check_next_ai.py
```

命令不打开数据库，只发送固定的合成指数样本到已配置的AI服务，输出脱敏状态及耗时。退出码0表示返回与校验均成功，1表示失败。命令会消耗一次正常模型请求的额度。
