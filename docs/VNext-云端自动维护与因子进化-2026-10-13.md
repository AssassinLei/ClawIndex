# ClawIndex VNext 2.1：持续运行、自动维护与因子进化

## 日常使用

添加指数即可：后台准备行情、修复历史缺口，工作日自动更新并生成个人判断。网页关闭后云端后台仍继续工作。原有巡检 Loading、中文证据和 AI 解读保留。

没有登记真实持仓时，按**默认空仓**判断，界面与买卖提醒标注这一假设。真实持有者只需登记一次，之后在交易成交或状态改变时更新；不再每七天要求确认。旧版未确认的“目标投入完成度”不再阻挡方向判断，按默认空仓处理，但保留原始归档和报告。明确登记为“未知”的状态仍需修改。已有真实持仓不被重置。

没填写金额、现金和基金映射也能查看方向。旧市值不会被当作当前卖出金额；预算过期或成交后现金待确认时仍需核实金额相关信息。系统无法从指数接口知道真实交易，成交反馈仍由用户完成。

自动维护开启时，后台为尚未配置的指数自动开始研究，基础指标和专业因子默认纳入，**自动晋升默认关闭**。已有配置、主动暂停、回退后的停用状态保持原样；旧授权重新保存后才扩展至因子组合。需要新规则自动应用时，在“策略与研究”确认范围并保存，飞书渠道单独控制。数据不足只显示后台处理状态，不要求用户手动补历史。

## 自动维护机制

所有用户共享同一指数行情与接口额度。Tushare 请求全局间隔至少2.1秒，接口调用超时20秒、网络错误最多重试3次；权限错误立即分类，不记录含密钥的原始异常。

每轮先抓最近行情，之后按季度补缺失、异常 OHLC 和旧版来源未核实的历史；默认从2016年或更晚的指数基期开始。每轮至多5个价格接口请求，补充接口每种至多2个请求，避免初始化一次拉完整历史拖住队列。价格与专业指标分开处理，重启后依据已保存数据和维护状态续接；有待补窗口时自动续跑。接口返回空的旧窗口暂缓6小时，再定期重试，继续处理其他窗口。新行情优先，不把前向填充当成补缺。

申万基础指标由 `sw_daily` 提供；适用宽基补充 `index_dailybasic`；国内指数专业技术指标由 `idx_factor_pro` 提供，完整保存78项技术字段。接口返回的专业行情字段不覆盖价格数据的金额单位。国际指数继续使用实际可得价格，不能假设也有国内 PE/PB 或专业因子。

专业接口权限不足延后24小时重试，网络失败延后1小时重试，价格规则及退出判断继续。最近交易日因子尚未发布时，后台定期重新拉取；冻结候选及前向观察等待同一交易日完整数据。若已经漏掉观察日，仍隔离候选，不事后伪造观察。权限问题不能靠程序补造数据，管理员需提供有效凭据与接口权限。

历史修订追加版本，保留证据；专业补充的可用时间记录为实际取得时刻。历史回测仍按盘后可知、下一时段执行的研究假设，不能宣称取得了完整历史发布时点。旧代码被确认后，后台自动补核实标的身份。

## 多因子如何进入进化

程序不把78个高度相关指标投票成“置信度”。四个固定组合与原均线策略在同一评估窗口比较：

| 组合 | 入场要求 | 主要目的 |
| --- | --- | --- |
| 价格风险过滤 | 20日年化波动不超过45%；120日回撤不超过25% | 限制高波动时入场 |
| 趋势与动量确认 | MACD快慢线差高于信号线；正向动向大于负向；趋势强度至少20；12日相对强弱45—75 | 限制弱趋势和过热追涨 |
| 估值与量能过滤 | PE/PB各自历史分位不高于85%；成交额至少20日均值的80%；60日动量为正 | 检查估值与量能环境 |
| 波动与通道过滤 | 真实波幅/点位不超过4%；位于布林中轨至上轨之间；24日相对强弱不高于75 | 限制波动与偏离 |

这些阈值是版本化的研究假设，不能解释成“已经证明有效”。只过滤新增买入；低于均线达到连续确认退出条件时，因子缺失或估值偏低均不能取消退出。

另提供全部已收集技术、基础及派生因子的开发区间探索：观察与未来20日收益、未来20日最低收盘变化的秩相关。标签不会越过开发区间边界；不按这张表挑赢家或临时调阈值。重叠窗口、重复指标、非平稳与多重检验意味着这些相关系数既不是胜率，也不是显著性证明。

完整覆盖共同评估窗口的组合才参选，缺失组合自动跳过，保留原规则。最多3个均线 ×（原规则+4个因子组合）×2种成本×2种延迟，合计最多60情景。默认年度180情景额度跨配置累计，因此最多支撑3轮完整60情景研究；部分组合不可用时用量减少。保持有限试验，不能每天重新筛选直到碰巧获利。

先仅在60%开发区间选一个候选，再检查20%验证、20%测试及成本/延迟压力；失败不改挑第二名。邻近稳定性比较只在同一因子组合内进行。历史合格后固定参数，默认63个未来实际观察交易日，仍通过回撤、收益损失、最低持有时间和交易次数检验；只有授权有效且条件通过才晋升，保留回退及审计。最多亏损20%等门槛是研究条件，不能保证真实账户最大亏损。

本版本不自动学习新因子定义、不自动优化这些固定阈值，也不连接交易账户。指数代理模拟不能代替真实基金净值、成交、分红、汇率和全账户风险计算。

## Linux 云端部署

根目录 `Dockerfile`、`compose.yaml` 和 `.env.cloud.example` 可用于同一 Linux 主机。网页、后台分别运行，共享两个命名卷保存数据库和备份，镜像不包含本地数据库、密钥或报告。进程退出由 Docker 恢复；服务器重启后恢复运行。不要用 NFS/多台主机共享 SQLite。

镜像从官方固定 SQLite 3.51.3 源码构建，校验 `sqlite3.c` 的官方 SHA3，构建时和启动时检查 Python 实际链接的库。包含官方 WAL-reset 修复，不依赖系统自带 SQLite 是否更新。

首次部署，在服务器项目目录运行：

```bash
cp .env.cloud.example .env.cloud
# 在服务器填写 TUSHARE_TOKEN；AI密钥可选。
docker compose build
```

**已有新版数据**：先在本地关闭旧服务，或用一致性备份命令导出 `quant_system_next.cloud-export.db`，再上传这一份。不要复制运行中孤立的 `.db` 文件而遗漏 WAL。

```bash
docker compose create worker web
docker compose cp ./quant_system_next.cloud-export.db worker:/data/quant_system_next.db
docker compose run --rm --user root --entrypoint sh ops -c 'chown 10001:10001 /data /data/quant_system_next.db /backups'
docker compose run --rm ops doctor
docker compose up -d --wait
```

**全新空库**：用下面命令代替上述上传步骤，不能对已有库执行初始化：

```bash
docker compose run --rm ops init
docker compose up -d --wait
```

端口默认只绑定服务器127.0.0.1。沿用用户名登录，因此使用现有私有反向代理、VPN或SSH隧道访问；不要直接对公网开放账号页面。例如：

```bash
ssh -L 8502:127.0.0.1:8502 your-user@your-server
# 本机浏览器打开 http://127.0.0.1:8502
```

常用运维：

```bash
docker compose ps
docker compose logs --tail=100 worker
docker compose restart worker web
docker compose run --rm ops backup --output /backups/before-update-20261013.db
```

备份文件名必须唯一。备份使用 SQLite backup API，并检查完整性和外键，支持后台运行时执行。本地导出也可用：

```powershell
.\.venv\Scripts\python.exe -m clawindex_next --db quant_system_next.db backup --output quant_system_next.cloud-export.db
```

更新代码时先一致性备份，获取新代码并 `docker compose build`，再 `docker compose up -d --wait`；数据库保留在卷中，**不需要每次重新上传数据库**。本次没有新增 schema，已有 schema 2 库无需再次迁移。更早的 schema 1 按原手册停服务、备份、显式升级。

后台收到 SIGTERM 后完成当前小段工作并停止，释放心跳；强杀时任务按租约恢复。连续3次循环异常主动退出；20分钟没有完成任务/同步等实际进展时由自身 watchdog 退出，再由 Docker 重启。健康检查报告状态，本身不负责重启；没有依靠 unhealthy 自动恢复的错误假设。日志轮转限制为3份，每份10MB。备份需另存服务器之外，命名卷不是异地备份。

## 验证范围

Windows 回归包含默认持仓、内部缺口恢复、分批续跑、专业权限降级、修订证据、不读未来数据、固定组合授权、全部因子开发探索、延迟发布续接、在线备份和后台停止恢复。

`.github/workflows/vnext-linux.yml` 会构建 Linux 镜像并运行同一回归，在一次性离线数据库上检查页面、任务、worker 崩溃恢复、SIGTERM 清理和备份；不使用真实通知渠道或行情账户。

当前开发机未安装 Docker 或可用 Linux/WSL；本地测试通过不代表 Linux 镜像和云服务器已经验收。需要代码提交到 GitHub 后查看此 CI 结果，再部署到实际服务器。另有只读实时接口探测报告 `reports/2026-10-13-factor-access-probe.json`，不会写行情或触发真实提醒。
