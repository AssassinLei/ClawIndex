# 整体系统Review与修复

本次检查新版的行情维护、信号计算、个人判断、执行反馈、策略研究与进化、机会雷达、通知、后台调度及云端运行入口。沿用账号名登录、默认空仓、用户手动交易的既有产品约定。

重点是让同一份有效证据贯穿“判断—展示—反馈—通知—研究”，并让后台在数据变化后继续工作，而不只是检查页面能否打开。

## 发现并处理的问题

| 问题 | 原来的影响 | 修复后的行为 |
|---|---|---|
| 已处理反馈只绑定一次判断ID | 同一轮信号因日切、行情修订而生成新ID后，已提交、成交或暂缓可能重新显示为待买卖 | 按用户、监控、操作及规则触发轮次识别同一指令，延续已处理状态；阅读确认不会撤销成交反馈。真正的新一轮信号仍可出现 |
| 未发送买卖提醒绑定旧判断 | 持仓、预算或证据更新后，旧提醒过期，但新判断被原去重记录挡住，造成漏发 | 将尚未发送的提醒绑定到最新有效判断，保留重试次数和退避；已发、已取消及尝试耗尽的记录不复活 |
| 同一交易日的旧证据仍被认为有效 | 行情或因子发生修订但尚未重算时，页面和发送流程可能使用旧判断 | 页面、提醒和持仓确认共同校验数据修订；旧计算版本也会失效。允许记录历史反馈，阻止它覆盖当前持仓 |
| 最后一次投递中断后的收尾不完整 | 普通提醒可能一直显示发送中，机会提醒可能发生第4次尝试 | 租约过期后将已耗尽3次尝试的记录结束为失败，不无限排队或超限重发 |
| 行情与因子并发写入 | 因子请求期间，另一任务写入新数据；先前读取的旧行可能覆盖新因子 | 在数据库写锁内读取最新修订再合并，保留其他来源的新字段 |
| 来源未知的旧价格参与有效计算 | 迁移价格虽标记来源未知，规则仍可能使用它产生有效操作 | 来源未核实的旧价格不作为有效价格输入，后台重新获取后再参与判断；计算版本升级为 `factor_features_v3` |
| 缺历史进入冷却后被当成完成 | 剩余缺口暂时不能重试时，任务的pending状态可能被清掉 | 有缺口就保留待修复状态，并保存实际下次可重试时间；冷却到期后自动接续 |
| 专业因子的异常影响自动维护 | 临时失败可能丢失自动重试安排；异常日期/字段可能中断已取得价格后的流程 | 保留因子待重试状态和时间；可识别的解析异常按可选指标失败处理，价格规则及退出判断继续使用有效价格 |
| 前向模拟使用已过去的开盘价 | 候选在开盘后才生成，或前一天证据在次日开盘后才处理，仍可能按过去的开盘模拟成交 | 同时检查真实冻结时间、上次实际观察时间与开盘时间；不能在过去成交，候选和持有对照使用同一约束 |
| 分段检验漏掉边界当天收益 | 验证/测试第一天的大跌可能因切片起点重置被漏算 | 使用分段前一日的收盘作为起点，完整计算边界收益、回撤与成本/暴露对照 |
| 格式异常的分类目录覆盖旧目录 | 接口非空但字段不对时，可能把完整目录替换为空 | 未取得有效分类行时保留已有目录，标记未完整，后台重试 |
| 当天同步完成后不再重算个人判断 | 之后修改持仓/预算，或共享数据新增修订，可能要等下一天才更新 | 按数据修订、个人输入、计算版本和评估日安排后台重算；已有行情可复用，不重复拉取。相同输入不会每轮生成任务 |

## 升级后的可见变化

- 同一轮信号已记录处理结果后，重新巡检不会再次提示重复下单。
- 行情或输入已变化而新判断未就绪时，显示“等待更新”，不沿用旧操作金额。后台自动重算完成后恢复显示。
- 首次升级后，旧计算版本的结果需要重算；来源未知的旧价格需要重新获取。后台自动维护开启时会接续完成，无需手工修改数据库或维护数据。
- 旧版前向候选如果没有可靠的实际冻结时间，将保留记录但停止用于晋升，说明“模拟成交时间校验已升级”。当前生效策略不因此自动回退；后续研究重新观察。
- 更新规则仍不代表自动交易，真实持仓由用户确认。默认空仓、原渠道开关和账户约定保留。

更新后同时重启 **web与worker**；没有新增数据库表或表结构迁移要求。

## 验证与边界

新增 `tests_next/test_system_review.py` 复现上述关键场景，另用原有测试检查每日进化、长期观察、个人隔离、Webhook、页面、启动、备份和迁移。具体结果见 `reports/2026-10-15-system-review-acceptance.md`。

测试使用隔离数据库、假行情服务及假发送函数；没有启动生产worker或向真实Webhook发送消息。没有为本次检查改写生产数据。

另对本地数据库进行了只读状态检查，确认存在历史缺口收据状态误判。调度器和共享行情缓存均已加入兼容判断，升级后按重试时间恢复处理，不需要人工改库。私人运行计数仅保存在本地验收报告；此检查不代表云服务器的实时状态。

开发机没有Docker环境，本次不能确认实际云服务器网络、容器构建和Linux长期运行效果。历史检验与软件测试也不能证明策略有持续收益优势。外部Webhook缺乏端到端幂等确认时，网络/进程中断后的有限重试仍可能重复送达；此次修复保证尝试有上限，不声称外部消息恰好送达一次。
